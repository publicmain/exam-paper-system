## 回滚边界

| 阶段 | 回滚方式 | 数据影响 |
|---|---|---|
| 1–2 | `git revert` | 无 |
| 3 | 删 `apps/student-web`，停 staging 服务 | 无 |
| 4a/4b | revert 后端两处改动（都向后兼容） | 无 |
| 4c/4d–7 | 新端下线，旧端原样可用 | 无 |
| 8 | 重新播种 staging | 只影响 staging |
| 9 | **关灰度开关**（秒级） | 无 —— 两端同一个库、同一套业务规则 |
| 10 | **无法回滚** —— 删代码、关旧通道之后没有退路 | 需要观察期把关 |

**关键设计**：阶段 1–9 全程**两个前端共用同一个 API 和同一个数据库**，
所以任何时候切回旧端，学生的进度、成绩、词队列都在。
真正不可逆的只有阶段 10。

## 尚需用户决定的问题

1. **`/student/*` 的作业（homework）与 AI 家教（tutor）怎么办？**
   它们在教师时代的学生外壳里，不属于「英语学习 App」七步链，也不属于
   四个独立页面。是并入新端、独立成第三个产品，还是下线？
2. **历史成绩要保留多深？** `MyHistory.tsx` 里有申诉、重做（practice）、
   技能画像、成绩趋势图。新端的 `/app/scores` 保留哪些？
3. **跨设备 AirDrop 接力（`#h=` 令牌）还需要吗？** 账号制之后学生在
   第二台设备上直接登录即可，这套机制可以整体删除。
4. **旧二维码物料**（墙上贴的、大屏显示的）什么时候停印/停显示？
   这决定 `/scan/:token` 适配器要活多久。
5. **灰度的粒度**：按班级还是按学生名单？
6. **观察期长度**：阶段 10 的「2 个完整教学周」是否够。
