## 数据与顺序

1. 获取用户对本机正式数据库备份的单独同意，再执行只读、一致性备份及回读校验。备份位于本副本 `.local/badges-release`，不入 Git 或镜像。当前此步骤待同意。
2. 本地迁移预演、权限/并发测试及三个应用回归全部通过后，发布 API。仅运行 Prisma 增量迁移，不执行 seed、修分或造数脚本。
3. API 健康及新增接口通过，再发布学生端与教师端，检查正式 API 地址和全部 16 个 GLB 的内容校验值。
4. 记录正式部署 ID、版本、迁移与线上验收结果。正式成功之前不把本地测试描述为上线成功。

迁移仅新增徽章、收藏初始化、关闭的班级周目标表及可空通知字段；保留历史行。若回退，先恢复前端和 API 的上一成功部署；保留新增表与已经授予的徽章，不通过删表回滚。
