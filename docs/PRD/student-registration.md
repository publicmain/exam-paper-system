# 学生注册 —— 网站式自助注册（密码 + 昵称 + 头像）

> 2026-08-26 定稿。**取代** student-auth-and-home.md §6.3 的「扫码后设 PIN」
> 与后来的「集体注册窗口」方案 —— 两者均未真正触达学生（见 §1），
> 教师实测后否决，改为本方案。

## 1. 背景：为什么推翻前两版

| 版本 | 方案 | 死因 |
|---|---|---|
| v1（8/25） | 扫码签到后弹「设 PIN」卡 | 前端触发线**从未接上**（`setGate('setpin')` 全文件零调用），学生从没见过这张卡 |
| v2（8/26 上午） | 教师开「注册窗口」，全班课上集体认领 | 教师实测：①已交卷的学生重扫被「不能再修改」挡死——注册课那天全班都是已交卷状态，流程对全班都断；②增加教师课堂负担，被明确否决 |

教师定案（2026-08-26）：**像普通网站一样注册**。打开 app 弹注册卡，
设密码、选昵称、选头像，仅此而已。不要教师开窗，不要「稍后再说」。

### 1.1 身份模型的取舍（教师已知情并拍板）

自助注册 = 先到先得。理论上同学可抢注他人名字。接受此风险的理由：

1. **设备即身份的延续**——弹卡的设备是长期查该生本人成绩的设备
   （localStorage 存着他的名字），远强于「拿到二维码」；
2. 全班 35 人互相认识，冒用当天即暴露；
3. **教师重置密码是兜底**：重置瞬间对方所有登录立刻失效
   （studentAuthVersion 撤销机制保留）。

## 2. 学生视角流程

### 2.1 注册（一次性，打开 app 即弹）

触发点：`/my-lesson`、`/my-history`、`/me` 任一页面加载时，
若「本机已知姓名 且 该生未注册」→ 弹全屏注册卡，**不可跳过**：

```
┌────────────────────────────┐
│  你好，曾义洋               │
│  完善你的账号，以后任何设备  │
│  都能登录                   │
│                            │
│  头像   [🦊][🐼][🐯]…[上传] │  ← 可选，默认第一个
│  昵称   [曾义洋________]    │  ← 默认真名，可改
│  密码   [______________]    │  ← ≥6 位，字母数字均可
│  再输一遍 [____________]    │
│                            │
│  [ 完成注册 ]               │
└────────────────────────────┘
```

- 本机**没有**姓名（全新设备）：卡顶部先让他输姓名对花名册，
  同名多人时选班级消歧 —— 与登录卡同一套交互。
- 成功即**自动登录**（发 30 天 token），无缝回到他本来要看的页面。
- 已注册的学生永远不会再见到这张卡。
- 教师「学生视角」（teacher_view 令牌）下不弹。

### 2.2 平时在校

扫码 → 签到 → 答题，**与现在完全一致**，不涉及密码。

### 2.3 在家 / 换设备

`/me` 登录卡：姓名 + 密码 → 30 天免登录。头像 + 昵称显示在
`/me` 顶部与 `/my-lesson` 问候区。

### 2.4 忘记密码 / 冒用处置

教师在花名册点「重置密码」→ 该生所有设备登录立刻失效 →
他下次打开 app 重新弹注册卡设新密码。连错 5 次锁 15 分钟（沿用）。

## 3. 规则

| 项 | 规则 |
|---|---|
| 密码 | 6–32 位任意字符；纯数字时沿用弱 PIN 黑名单（全同/顺子）；全同字符一律拒 |
| 昵称 | 1–20 字符，默认真名，不要求唯一 |
| 头像 | 可选。预设 emoji 之一（存 `emoji:<char>`）或上传图片：前端裁到 128×128 JPEG，data URL ≤ 64KB，存 `User.avatar` 文本列（35 人 × ~20KB，无需外部存储） |
| 注册资格 | 该 User 尚无密码（`pinHash IS NULL`）即可注册；已注册 → 409 `already_registered`，提示去登录 |
| 限流 | 注册 10/60s/IP；状态查询 60/60s/IP |

## 4. 改动清单

### 4.1 数据（一次 migration）

- `User.nickname TEXT NULL`
- `User.avatar   TEXT NULL`
- 密码复用现有 `pinHash / pinSetAt / pinFailedCount / pinLockedUntil /
  studentAuthVersion`（不重命名 —— 不做无必要重构）

### 4.2 API

| 端点 | 变化 |
|---|---|
| `POST /student-auth/register` | **新增**。name(+studentId 消歧) + password + nickname? + avatar? → 校验资格 → 写库 → 发 30 天 token（带 av） |
| `GET /student-auth/registration-status` | **新增**。name(+studentId) → `{registered}` 或同名候选。弹不弹卡由它定 |
| `POST /student-auth/login` | 密码预检从 `^\d{6}$` 放宽为长度 6–32；响应带 nickname/avatar |
| `GET /student-auth/me` | 响应带 nickname/avatar |
| `POST /student-auth/set-pin` | **移除认领窗口闸**（claim_window_closed）。端点保留（不重构），实际弃用 |
| 认领窗口 open/close/status、教师重置、学生视角 | 保留不动；注册台页面文案改为纯看板 |

### 4.3 前端

| 文件 | 变化 |
|---|---|
| `components/RegistrationSheet.tsx` | **新增**：全屏注册卡（无跳过） |
| `lib/registration.ts` | **新增**：触发判定 + 状态缓存（已注册的本机缓存，不每次打接口） |
| `pages/MyLesson.tsx` / `MyHistory.tsx` / `Me.tsx` | 挂注册卡；Me 的「PIN」文案全部改「密码」，登录/改密输入框放开为任意字符 |
| `pages/MorningQuizScan.tsx` | ①已交卷重扫：`already_final_submitted` 加入「门厅」分支 → 显示「📊 我的成绩」大按钮而非死档红墙；②删除从未接线的 setpin 门与 PinSetupCard 引用 |
| `components/PinSetupCard.tsx` | 删除（v1 遗留，从未被触达） |
| `components/exam/shared/Highlighter.tsx` | iPad 点词修复：触屏抬手位移阈值 8px→18px（手指落点抖动远大于鼠标），时长阈值同步放宽 |
| `pages/ClassRegistration.tsx` | 开窗按钮撤下，改纯看板（谁已注册 / 学生视角） |

### 4.4 不做的事

- 不改扫码答题主流程；不动教师端判分/出卷；不重命名 pin* 字段；
- 不做邮箱/手机验证、不做找回密码自助流程（教师重置即恢复通道）。

## 5. 测试计划

1. 单测：密码格式（长度/弱纯数字/全同字符）、register 资格判定、
   同名消歧、already_registered
2. 生产 E2E（测试学生）：注册 → 登录 → 错密码 → 重置 → 旧 token 失效 →
   重新注册
3. 浏览器：打开 /my-lesson 弹卡（无跳过按钮）→ UI 注册全流程 →
   头像昵称显示；已交卷重扫见「我的成绩」按钮
4. iPad 点词：桌面触屏仿真验证；**真机 iPad 需教师复验**（无真机）
