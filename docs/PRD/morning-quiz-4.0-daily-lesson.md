# 早测 4.0 —— 从「限时测验」到「每日一课」

> 状态：**设计稿，待评审**　·　起草 2026-08-25　·　决策人：叶老师
> 前置：[morning-quiz-3.0-levels-and-vocab.md](./morning-quiz-3.0-levels-and-vocab.md)（五层 + 词汇主线）

---

## 1. 为什么要改

### 1.1 现在的形态

每天两个固定窗口：**08:30–09:00** 正式窗、**16:00–17:30** 第二作答窗。
9:00 强制收卷（收成暂存）、17:30 收尾（最终化）。学生扫码进场、限时作答、
交卷看答案，第二天教师判完简答题出分。

### 1.2 三个已经量到的病症

**病症一：参与率。** 2026-08-25 全班 35 人，**11 人扫码**。其中毛思琳
扫了码一题没答，9:00 被强制收卷记 0 分。这不是个案 —— 上周同样的低位。

**病症二：交卷即离场。** 学生打开逐题详情 10 人，点进词汇入口 2 人
（转化率 20%）。原因不是入口不显眼 —— 是**他 9:00 就得去上课**。
词汇、错题复盘这些真正产生学习的环节，被挤在交卷后的三分钟里。

**病症三：补丁叠补丁。** 第二作答窗本身就是给「来不及答完」打的补丁；
`releaseStrandedDrafts` 是给「第二窗没开成」打的补丁的补丁。每加一个
时间窗，就多一圈边界条件。

### 1.3 病根

**把「评估」和「学习」塞进了同一个 30 分钟窗口。** 两者对时间的需求
截然相反：评估要限时（考试能力就是限时能力），学习要从容（背单词、
弄懂错题急不得）。挤在一起的结果是两头都不讨好。

而且 —— **出勤已于 2026-08-24 全面停用**。既然系统不再回答「几点到校」，
固定窗口在保护的东西已经不存在了。

## 2. 新形态：每天一节课

### 2.1 一句话

**每天一节课，当天任何时间完成都算数。** 课分三段，完成三段 = 今天的课
完成。老师看的是完成度，不再是出勤。

### 2.2 课的结构

| 段 | 内容 | 时长 | 完成判定 |
|---|---|---|---|
| **① 读** | 当天的阅读卷（含卷内词汇题） | **不限时**（显示「通常 15 分钟」） | 最终提交（`finalSubmittedAt` 非空） |
| **② 背** | 今日词汇：新词翻卡 → 自测 | 不限时，约 3–5 分钟 | 当天复习次数 ≥ 今日目标 |
| **③ 补** | 错题重练 | 不限时，约 3 分钟 | 当天错题队列清空 |

**为什么读段也不限时**（2026-08-25 修正，原设计是 20 分钟倒计时）：

1. **实测数据否决了那个数字。** 近两周 79 人次「扫码→交卷」的真实用时：
   中位 **12.4 分钟**、75 分位 19.9、90 分位 **23.6**，**24% 超过 20 分钟**。
   20 分钟会每四人打断一个，且专打高层级（雅思真题层今天用 13–16 分钟）。
2. **计时防不住它声称要防的东西。** 全天开放后，学生可以点开看题、退出去
   查词典问同学、再回来填。倒计时对此毫无作用（除非进入后锁死不许退出，
   那体验更糟），它只提供「成绩还是真实的」的错觉。
3. **它与全天开放互相抵消。** 全天开放是为降低门槛（随时能做），计时又要求
   「必须有完整 20 分钟整块时间」——晚上只有 10 分钟碎片的学生就不做了。
4. **限时能力应在定期模考里练**，不是每天日常练习。每天被计时练的是
   「被计时的紧张感」，边际价值递减。

**取而代之**：页面显示「通常 15 分钟左右」（数字来自真实中位数，仅作参考）；
仍记录 `startedAt → submittedAt` 的实际用时，**作为教师观察指标**——谁花了
两小时、谁 1 分钟交白卷（2026-08-25 李永轩就是 1 分钟交、0 分），这些有
教学价值。真出现拿两小时刷满分的，个别处理，不为它给全班上枷锁。

**背段和补段同样不限时**：这两段是学习不是测量，卡表只会让学生糊弄。

### 2.3 完成判定必须可达成（关键）

完成度设计最容易犯的错是定一个**永远达不到**的目标 —— 那样完成度就成了
另一个「只涨不落的债」，激励反向。所以：

- **背段的「今日目标」= min(今日到期词数, 动态配额)**，配额就是现有的
  `reviewBatchSize`（5–20 张）。积压 200 词的学生，今天过完 20 张就是
  100% 完成，不欠账。
- **补段**：今日错题队列本来就是空的 → 直接算完成（不是「无法完成」）。
- **读段**：交卷即完成，分数高低不影响完成度。**完成度衡量的是「做了」，
  不是「做得好」** —— 分数另有去处。

### 2.4 一天没做完怎么办

23:59 收尾：未最终提交的答卷自动最终化并公布答案（沿用现有 cron 逻辑，
只是时刻从 17:30 挪到 23:59）。当天没完成的段落**不补、不累积到明天** ——
第二天是新的一课。错题和生词本身会自然滚动到明天，不需要「补作业」机制。

## 3. 学生端：今天的课

### 3.1 入口

学生扫码（或直接打开 `/my-lesson?name=…`）后落到的第一页不再是卷子，
而是**今天的课**：

```
┌─────────────────────────────────┐
│  今天的课 · 8月26日 周三          │
│  ●●○   2/3 完成                  │
├─────────────────────────────────┤
│ ① 读  《Working Against the Clock》│
│    8 题 · 通常 15 分钟            │
│    ✓ 已完成    7/9 分  →         │
├─────────────────────────────────┤
│ ② 背  今日词汇                    │
│    23 个词 · 约 4 分钟            │
│    ● 进行中   8/20   继续 →      │
├─────────────────────────────────┤
│ ③ 补  错题重练                    │
│    3 道 · 约 3 分钟               │
│    ○ 未开始          开始 →      │
├─────────────────────────────────┤
│  🔥 连续 4 天完成                 │
└─────────────────────────────────┘
```

**设计要点**：

1. **三段并列，不强制顺序。** 学生可以先背词再读文章。强制顺序会复制
   现在「词汇挡在成绩前面」的老毛病。
2. **每段显示预计时间**，且都是小数字（15 / 4 / 3 分钟）。「今天要花
   22 分钟」比「今天有一节课」好接受得多。注意措辞是「通常」不是
   「限时」——它是参考，不是约束。
3. **读段完成后显示分数**（判分前显示 `— / 9`），点进去是逐题详情 ——
   现有的 `/my-history/submission/:id` 原样复用。
4. **连续完成天数**取代现在的「连续复习天数」，口径沿用已有的上学日
   算法（`streakFromDays`，只隔周末不断 + 每学期 2 次豁免）。
5. **未开始的段落不用红色**。这是学习任务不是欠债，视觉上不制造压力。

### 3.2 读段的时间提示

不设倒计时、不设开始确认弹窗（原设计有，已撤销 —— 见 §2.2）。
段落卡片上只写一行参考：

> 8 题 · **通常 15 分钟**

学生自己决定什么时候做、做多久。系统在后台记录实际用时，只给教师看。

### 3.3 完成后

三段全绿时，页面顶部变成一句话：

> 🎉 今天的课完成了 · 连续 5 天

不做额外奖励（徽章、积分）。34 人的班里，攀比机制的副作用大于收益。

替换现在的出勤视图（出勤已停用，那块区域正好空出来）：

```
G11 · 8月26日            完成 18/35

姓名        读   背   补    分数
刘亦佳      ✓    ✓    ✓     8/9
叶书瑞      ✓    ●    ○     5/9
李永轩      ✓    ○    ○     2/9
毛思琳      ○    ○    ○      —

```

- 一眼看到**谁一点没动**（三个 ○）—— 这是要找的人；
- 「读✓ 背○」的学生说明卷子做了、词没背 —— 这是明天早读要点名的人；
- 分数仍在，但退居末列。**完成度是过程指标，分数是结果指标**，老师
  两个都要，但每天盯的是前者。

保留现有的 `classTop`（今天该讲哪几个词）—— 它和完成度看板是一对。

## 5. 技术改造清单

### 5.1 时间模型（改动最小，因为机制可复用）

现有的**暂存提交 / 最终提交**两段机制（为第二作答窗做的）**正好适配
全天开放**，不需要重写：

| 现在 | 改为 |
|---|---|
| `attendanceStart` 08:30 | **00:00**（当天） |
| `quizEnd` 09:00 | **23:59**（当天） |
| `makeupStart/End` 16:00–17:30 | **废弃**（字段保留，不再自动开窗） |
| 9:00 `lockPastSessions` 收成暂存 | **23:59 收尾并最终化** |
| 16:00 `autoOpenSecondWindows` | **删除调用** |
| `releaseStrandedDrafts` 判据 | 改成「过当天 23:59」 |
| 扫码 token 有效期绑 `quizEnd`/`makeupEnd` | 绑当天 23:59 |

**新增 `StudentSubmission.startedAt`**（首次打开卷子的时刻）—— 仅用于
统计实际用时给教师看，**不参与任何截止判定**。全体学生的截止时刻统一是
当天 23:59。

⚠️ 现有 74 处 `quizEnd` 引用中，大部分是「窗口是否开着」的判断 ——
改成全天后这些判断恒真，但**不能直接删**，因为它们同时承担
「这场是不是今天的」职责。逐处审。

### 5.2 新增：课程完成度

新模块 `apps/api/src/lesson/`：

```
GET /api/lesson/today?name=&studentId=
→ {
    date, streakDays, completed: 2, total: 3,
    segments: [
      { key:'read',  status:'done',    label:'《…》', detail:'8 题 · 通常 15 分钟',
        score:7, maxScore:9, href:'/my-history/submission/…' },
      { key:'vocab', status:'partial', progress:8, target:20, href:'/my-vocab/review?…' },
      { key:'drill', status:'todo',    progress:0, target:3,  href:'/my-mistakes/practice?…' },
    ]
  }
```

完成度**实时算，不落表** —— 三段的数据源都已存在
（`StudentSubmission.finalSubmittedAt` / 当日 `WordReviewLog` 计数 /
`MistakeEntry` 待练数），没必要引入会不一致的冗余状态。

只有**连续完成天数**需要落表（要跨天累计）：新表 `DailyLessonCompletion`
`(studentId, date, readDone, vocabDone, drillDone, completedAt)`，
由 23:59 的 cron 写入当天快照。

### 5.2b 完成度的语义（外部复审两轮都点名的地方）

前一版把「完成」定义成 `readDone = finalSubmittedAt != null`，再让
23:59 的 cron 给所有开了卷没交的自动最终化。两个审查都指出这会制造
**幽灵完成**：学生 8:35 扫码开卷、只读了标题就去上课，23:59 被系统
替他交卷，第二天课程页显示「读段 ✅」，连续天数照涨。完成度一旦能被
系统凭空发放，它就不再能回答「这孩子今天到底学没学」——而这正是
4.0 要它回答的唯一问题。

以下五条是 A 阶段动工前必须先落地的前置（记为 **A0**）：

#### (1) 显式提交与系统收尾必须是两种东西

`StudentSubmission` 增加 `submitSource`（`student` | `system_eod` |
`teacher`）与 `autoFinalizeReason`。

- `student` —— 学生自己点的交卷，**只有这种计入完成度和连续天数**
- `system_eod` —— 23:59 收尾，只用于「把卷子定住不让明天再改」，
  在课程页显示为「未完成（已自动收卷）」
- `teacher` —— 教师代交，按 `student` 计但留痕

同时给 `system_eod` 加一条最低门槛：作答题数为 0 的卷子**不产生
AnswerScript、不落完成**，就当没开过（现在的行为已经是不产生 script，
这里只是把它写进契约，防止后续重构时被"顺手补齐"）。

#### (2) 每日目标进入时冻结，不能是动态分母

背段目标「今天复习 20 个」、补段目标「练完 3 道错题」都是从当下数据
现算的。学生早上看到 3 道、下午又错了两道就变成 5 道 —— 目标在他背后
往后退，这是最挫败的一种设计。

`DailyLessonCompletion` 在**学生当天首次打开课程页**时创建，把三段的
目标数写死；当天之后新增的错题/生词进明天的课。

#### (3) `DailyLessonCompletion` 的字段要能解释自己

前一版只有 `(studentId, date, readDone, vocabDone, drillDone, completedAt)`,
事后完全无法回答「这个 ✅ 是怎么来的」。补齐：

```
studentId, date,
readTarget/readProgress/readDoneAt/readSource,
vocabTarget/vocabProgress/vocabDoneAt,
drillTarget/drillProgress/drillDoneAt,
targetsFrozenAt,      -- 目标快照时刻，对应 (2)
rulesVersion,         -- 完成规则的版本号，改判定口径时递增
autoFinalizeReason    -- 若当天被系统收尾，记原因
```

`rulesVersion` 是关键的一条：完成率是要拿来做决策的指标，口径改过而
历史数据不标版本，两周前后的数字就不可比。

#### (4) 23:59 不是一个可用的边界

**竞态**：600ms 自动保存与 23:59:00 锁卷会撞车，学生最后一次输入可能
写在锁之后被拒、也可能写进已锁的卷。
**不公平**：23:58 开卷的学生只有 2 分钟。

改为：
- 锁卷时刻 = `当天 23:59` 与 `开卷时刻 + 30 分钟宽限` 的**较晚者**，
  上限到次日 01:00（再晚就不是"今天的课"了）
- 锁卷前 60 秒前端出提示条，并**强制 flush 一次自动保存**
- 锁的执行按 submission 逐个判定，不做全表定时扫描

#### (5) 渲染器不能靠第一题推断

现在整卷的渲染方式由第一题的题型推出来。卷内词汇题上线后，一份卷子
里同时有阅读题和词汇题，第一题是什么完全是抽题顺序的偶然。
改为 `Paper.rendererKey` 显式存储，出卷时写入，缺失时回退到现有推断
并**打一条 warn 日志**（好知道还有多少存量卷子在走回退路径）。

## 6. 风险与取舍（诚实清单）

### 6.1 题目会泄露 —— 已知且接受

全天开放意味着早上做完的学生有一整天可以把答案告诉别人。缓解措施：

- **每人选项乱序**（`QuestionShuffleMap` 已存在，只需对新卷生效）——
  挡得住「第 3 题选 B」，挡不住「那篇讲生物钟的，判断题第一题选 TRUE」。
- **接受剩余风险**：这是校内日常练习，不是选拔性考试。抄来的分数没有
  任何用处，而抄词汇题的人下周还会被同一批词考到。

如果哪天需要一次真正的限时统考，另开一个「考试模式」的场次即可 ——
不要为了防作弊把每天的课也锁死。

### 6.2 没有 deadline，完成率可能更低

这是最大的不确定性。8:30 的集体时刻本身有推力：**所有人一起做**会带动
犹豫的人。改成全天后可能变成「晚点再说 → 忘了」。

对策：

1. **保留 8:30 的建议时间**，课程页显示「大家通常在 8:30 或 16:30 做」——
   社会证明比强制更有效；
2. **完成度看板给老师**，让「今天谁没做」在早读时可见 —— 把推力从系统
   转移到人；
3. **上线后两周对比参与率**。如果参与率不升反降，说明推力主要来自铃声
   而非自愿，那就把读段的窗口收回来（背段/补段保持全天）。

**这一条必须实测，不能靠推理。** 见 §8 度量。

### 6.3 不限时带来的新风险：慢工出满分

学生可以打开卷子、慢慢查词典、甚至问同学，然后填一份高分。

**为什么仍然接受**：
- 这与 §6.1 的题目泄露是同一个风险敞口，加倒计时也堵不住（他可以退出去查）；
- 完成度已取代分数成为主指标，刷高分的收益本来就低；
- `startedAt → submittedAt` 的用时记录让异常可见（花两小时的会在教师端跳出来）。

**兜底**：若某个学生长期用时异常且分数与课堂表现严重不符，是个体谈话问题，
不是产品问题。

## 7. 迁移方案（分三步，不一次切）

| 阶段 | 内容 | 前置 |
|---|---|---|
| **A0** | 完成度语义（见 5.2b）：`submitSource`、目标冻结、`DailyLessonCompletion` 完整字段、宽限期锁卷、`rendererKey` | 认证收口完成 |
| **A** | 上线 `/my-lesson` 课程页 + 完成度接口，**时间窗照旧**（8:30–9:00 / 16:00–17:30）。新完成度**影子运行**（算但不展示给学生），与旧口径并排看两周 | A0 |
| **B** | 放开时间窗：全天开放、读段不限时；关掉第二窗自动开启 | A 跑满**两个完整教学周**、新完成度影子运行且与旧口径差异可解释、回滚演练做过一次 |
| **C** | 教师端完成度看板替换出勤视图；`DailyLessonCompletion` 落表、连续完成天数上线 | B 稳定 |

**为什么不一次切**：时间窗逻辑有 74 处引用、cron 四个职责互相咬合，
一次全改的爆炸半径覆盖「学生能不能答题」这个最关键路径。分三步，每步
都可独立回滚。

**A 阶段可以在本周内上线**（改动只是新增页面和只读接口，不碰任何现有
时间逻辑）。

## 8. 度量（上线前先定好，避免事后找理由）

| 指标 | 当前基线（2026-08-25） | 目标 |
|---|---|---|
| 日参与率（读段完成 / 在读人数） | 11/35 = **31%** | ≥ 50% |
| 三段全完成率 | —（新指标） | ≥ 30% |
| 背段完成率 | 3/35 = **9%** | ≥ 40% |
| 补段完成率 | 1/35 = **3%** | ≥ 30% |
| 词汇「已开始」占比 | **25%**（169/683） | ≥ 40% |
| 读段实际用时 | 中位 **12.4** 分 / 90 分位 **23.6** 分（n=79，扫码→交卷） | 观察是否因不限时而显著变长 |

**红线**：B 阶段上线两周内，若日参与率低于 A 阶段基线，立即回滚读段
的时间窗。

**样本量的诚实说明**：单班 35 人、每天一个数据点，一周只有 5 个点。
「一周无下滑」在这个样本下几乎测不出任何东西 —— 一天有人请假就能
把周参与率推动 3 个百分点。所以 B 的前置改成两个完整教学周（10 个
点），并且时间窗的放开走 feature flag（`LESSON_ALL_DAY`），可以按班
灰度、可以一条命令回滚，不需要重新部署。

## 附：与 3.0 的关系

3.0 解决的是**内容**问题（五个难度层、词汇主线、卷内词汇题）。
4.0 解决的是**结构**问题（学习活动的时间和边界）。

3.0 的所有成果在 4.0 里原样保留 —— 卷子、词表推送、FSRS 调度、判分
流程一行不改，只是它们从「散落在两个时间窗里的动作」变成「一节课的
三个段落」。
