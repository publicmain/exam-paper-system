# 早测 4.0 —— 从「限时测验」到「每日一课」

> 状态：**设计稿，待评审**　·　起草 2026-08-25　·　决策人：叶老师
> 前置：[morning-quiz-3.0-levels-and-vocab.md](./morning-quiz-3.0-levels-and-vocab.md)（五层 + 词汇主线）

---

## 1. 为什么要改

### 1.1 现在的形态

每天两个固定窗口：**08:30–09:00** 正式窗、**16:00–17:30** 第二作答窗。
9:00 强制收卷（收成暂存）、17:30 收尾（最终化）。学生扫码进场、限时作答、
交卷看答案，第二天教师判完简答题出分。

### 1.2 三个已经量到的病症

**病症一：参与率。** 2026-08-25 全班 35 人，**11 人扫码**。其中毛思琳
扫了码一题没答，9:00 被强制收卷记 0 分。这不是个案 —— 上周同样的低位。

**病症二：交卷即离场。** 学生打开逐题详情 10 人，点进词汇入口 2 人
（转化率 20%）。原因不是入口不显眼 —— 是**他 9:00 就得去上课**。
词汇、错题复盘这些真正产生学习的环节，被挤在交卷后的三分钟里。

**病症三：补丁叠补丁。** 第二作答窗本身就是给「来不及答完」打的补丁；
`releaseStrandedDrafts` 是给「第二窗没开成」打的补丁的补丁。每加一个
时间窗，就多一圈边界条件。

### 1.3 病根

**把「评估」和「学习」塞进了同一个 30 分钟窗口。** 两者对时间的需求
截然相反：评估要限时（考试能力就是限时能力），学习要从容（背单词、
弄懂错题急不得）。挤在一起的结果是两头都不讨好。

而且 —— **出勤已于 2026-08-24 全面停用**。既然系统不再回答「几点到校」，
固定窗口在保护的东西已经不存在了。

## 2. 新形态：每天一节课

### 2.1 一句话

**每天一节课，当天任何时间完成都算数。** 课分三段，完成三段 = 今天的课
完成。老师看的是完成度，不再是出勤。

### 2.2 课的结构

| 段 | 内容 | 时长 | 完成判定 |
|---|---|---|---|
| **① 读** | 当天的阅读卷（含卷内词汇题） | **一旦开始 20 分钟倒计时** | 最终提交（`finalSubmittedAt` 非空） |
| **② 背** | 今日词汇：新词翻卡 → 自测 | 不限时，约 3–5 分钟 | 当天复习次数 ≥ 今日目标 |
| **③ 补** | 错题重练 | 不限时，约 3 分钟 | 当天错题队列清空 |

**为什么读段仍然限时**：雅思和 O-Level 都是限时考试，限时作答是必须
训练的能力。全天开放的是**何时开始**，不是**答多久**。学生可以晚上八点
开始，但一旦点开就是 20 分钟。

**为什么背段和补段不限时**：这两段是学习不是测量，卡表只会让学生糊弄。

### 2.3 完成判定必须可达成（关键）

完成度设计最容易犯的错是定一个**永远达不到**的目标 —— 那样完成度就成了
另一个「只涨不落的债」，激励反向。所以：

- **背段的「今日目标」= min(今日到期词数, 动态配额)**，配额就是现有的
  `reviewBatchSize`（5–20 张）。积压 200 词的学生，今天过完 20 张就是
  100% 完成，不欠账。
- **补段**：今日错题队列本来就是空的 → 直接算完成（不是「无法完成」）。
- **读段**：交卷即完成，分数高低不影响完成度。**完成度衡量的是「做了」，
  不是「做得好」** —— 分数另有去处。

### 2.4 一天没做完怎么办

23:59 收尾：未最终提交的答卷自动最终化并公布答案（沿用现有 cron 逻辑，
只是时刻从 17:30 挪到 23:59）。当天没完成的段落**不补、不累积到明天** ——
第二天是新的一课。错题和生词本身会自然滚动到明天，不需要「补作业」机制。

## 3. 学生端：今天的课

### 3.1 入口

学生扫码（或直接打开 `/my-lesson?name=…`）后落到的第一页不再是卷子，
而是**今天的课**：

```
┌─────────────────────────────────┐
│  今天的课 · 8月26日 周三          │
│  ●●○   2/3 完成                  │
├─────────────────────────────────┤
│ ① 读  《Working Against the Clock》│
│    8 题 · 20 分钟                 │
│    ✓ 已完成    7/9 分  →         │
├─────────────────────────────────┤
│ ② 背  今日词汇                    │
│    23 个词 · 约 4 分钟            │
│    ● 进行中   8/20   继续 →      │
├─────────────────────────────────┤
│ ③ 补  错题重练                    │
│    3 道 · 约 3 分钟               │
│    ○ 未开始          开始 →      │
├─────────────────────────────────┤
│  🔥 连续 4 天完成                 │
└─────────────────────────────────┘
```

**设计要点**：

1. **三段并列，不强制顺序。** 学生可以先背词再读文章。强制顺序会复制
   现在「词汇挡在成绩前面」的老毛病。
2. **每段显示所需时间**，且都是小数字（20 / 4 / 3 分钟）。「今天要花
   27 分钟」比「今天有一节课」好接受得多。
3. **读段完成后显示分数**（判分前显示 `— / 9`），点进去是逐题详情 ——
   现有的 `/my-history/submission/:id` 原样复用。
4. **连续完成天数**取代现在的「连续复习天数」，口径沿用已有的上学日
   算法（`streakFromDays`，只隔周末不断 + 每学期 2 次豁免）。
5. **未开始的段落不用红色**。这是学习任务不是欠债，视觉上不制造压力。

### 3.2 读段的时间提示

点「开始」时给一次明确确认：

> **开始后有 20 分钟，中途不能暂停。**
> 现在开始 / 待会儿再说

这是全天开放后唯一需要的仪式感 —— 让学生**自己选**何时进入限时状态，
而不是被 8:30 的铃声推进去。

### 3.3 完成后

三段全绿时，页面顶部变成一句话：

> 🎉 今天的课完成了 · 连续 5 天

不做额外奖励（徽章、积分）。34 人的班里，攀比机制的副作用大于收益。

## 4. 教师端：完成度看板

替换现在的出勤视图（出勤已停用，那块区域正好空出来）：

```
G11 · 8月26日            完成 18/35

姓名        读   背   补    分数
刘亦佳      ✓    ✓    ✓     8/9
叶书瑞      ✓    ●    ○     5/9
李永轩      ✓    ○    ○     2/9
毛思琳      ○    ○    ○      —
…
```

- 一眼看到**谁一点没动**（三个 ○）—— 这是要找的人；
- 「读✓ 背○」的学生说明卷子做了、词没背 —— 这是明天早读要点名的人；
- 分数仍在，但退居末列。**完成度是过程指标，分数是结果指标**，老师
  两个都要，但每天盯的是前者。

保留现有的 `classTop`（今天该讲哪几个词）—— 它和完成度看板是一对。

## 5. 技术改造清单

### 5.1 时间模型（改动最小，因为机制可复用）

现有的**暂存提交 / 最终提交**两段机制（为第二作答窗做的）**正好适配
全天开放**，不需要重写：

| 现在 | 改为 |
|---|---|
| `attendanceStart` 08:30 | **00:00**（当天） |
| `quizEnd` 09:00 | **23:59**（当天） |
| `makeupStart/End` 16:00–17:30 | **废弃**（字段保留，不再自动开窗） |
| 9:00 `lockPastSessions` 收成暂存 | **23:59 收尾并最终化** |
| 16:00 `autoOpenSecondWindows` | **删除调用** |
| `releaseStrandedDrafts` 判据 | 改成「过当天 23:59」 |
| 扫码 token 有效期绑 `quizEnd`/`makeupEnd` | 绑当天 23:59 |

**读段 20 分钟倒计时**是新逻辑：以 `StudentSubmission.startedAt`
（新字段）为起点，`startedAt + 20min` 与 23:59 取较早者作为该生的
个人截止时刻。

⚠️ 现有 74 处 `quizEnd` 引用中，大部分是「窗口是否开着」的判断 ——
改成全天后这些判断恒真，但**不能直接删**，因为它们同时承担
「这场是不是今天的」职责。逐处审。

### 5.2 新增：课程完成度

新模块 `apps/api/src/lesson/`：

```
GET /api/lesson/today?name=&studentId=
→ {
    date, streakDays, completed: 2, total: 3,
    segments: [
      { key:'read',  status:'done',    label:'《…》', detail:'8 题 · 20 分钟',
        score:7, maxScore:9, href:'/my-history/submission/…' },
      { key:'vocab', status:'partial', progress:8, target:20, href:'/my-vocab/review?…' },
      { key:'drill', status:'todo',    progress:0, target:3,  href:'/my-mistakes/practice?…' },
    ]
  }
```

完成度**实时算，不落表** —— 三段的数据源都已存在
（`StudentSubmission.finalSubmittedAt` / 当日 `WordReviewLog` 计数 /
`MistakeEntry` 待练数），没必要引入会不一致的冗余状态。

只有**连续完成天数**需要落表（要跨天累计）：新表 `DailyLessonCompletion`
`(studentId, date, readDone, vocabDone, drillDone, completedAt)`，
由 23:59 的 cron 写入当天快照。

### 5.3 前端

| 页面 | 改动 |
|---|---|
| `/my-lesson`（新） | 今天的课，成为学生端主入口 |
| 扫码落地页 | 从「直接进卷子」改为「先到今天的课」 |
| `MorningQuizTake` | 加 20 分钟个人倒计时（替代场次 `quizEnd` 倒计时）；开始前的确认弹窗 |
| `MyVocabReview` / `MyMistakesPractice` | 完成后回到 `/my-lesson`，而不是回成绩页 |
| `MyHistoryDetail` | 词汇横幅可以撤掉 —— 它的职责被课程页接管 |
| 教师端 | 出勤视图 → 完成度看板 |

## 6. 风险与取舍（诚实清单）

### 6.1 题目会泄露 —— 已知且接受

全天开放意味着早上做完的学生有一整天可以把答案告诉别人。缓解措施：

- **每人选项乱序**（`QuestionShuffleMap` 已存在，只需对新卷生效）——
  挡得住「第 3 题选 B」，挡不住「那篇讲生物钟的，判断题第一题选 TRUE」。
- **接受剩余风险**：这是校内日常练习，不是选拔性考试。抄来的分数没有
  任何用处，而抄词汇题的人下周还会被同一批词考到。

如果哪天需要一次真正的限时统考，另开一个「考试模式」的场次即可 ——
不要为了防作弊把每天的课也锁死。

### 6.2 没有 deadline，完成率可能更低

这是最大的不确定性。8:30 的集体时刻本身有推力：**所有人一起做**会带动
犹豫的人。改成全天后可能变成「晚点再说 → 忘了」。

对策：

1. **保留 8:30 的建议时间**，课程页显示「大家通常在 8:30 或 16:30 做」——
   社会证明比强制更有效；
2. **完成度看板给老师**，让「今天谁没做」在早读时可见 —— 把推力从系统
   转移到人；
3. **上线后两周对比参与率**。如果参与率不升反降，说明推力主要来自铃声
   而非自愿，那就把读段的窗口收回来（背段/补段保持全天）。

**这一条必须实测，不能靠推理。** 见 §8 度量。

### 6.3 20 分钟倒计时的边界

- 学生点开就走 → 20 分钟后自动交卷（沿用现有超时收卷逻辑）；
- 断网/切后台 → 倒计时以服务端 `startedAt` 为准，前端只是显示；
- 手滑点开 → 确认弹窗挡一道；真误触了，当天这份就是他的成绩（与现在
  8:30 误点进场一样，无新增风险）。

## 7. 迁移方案（分三步，不一次切）

| 阶段 | 内容 | 前置 |
|---|---|---|
| **A** | 上线 `/my-lesson` 课程页 + 完成度接口，**时间窗照旧**（8:30–9:00 / 16:00–17:30）。学生先习惯「三段一课」的结构 | 无 |
| **B** | 放开时间窗：全天开放 + 20 分钟个人倒计时；关掉第二窗自动开启 | A 跑满一周、参与率无下滑 |
| **C** | 教师端完成度看板替换出勤视图；`DailyLessonCompletion` 落表、连续完成天数上线 | B 稳定 |

**为什么不一次切**：时间窗逻辑有 74 处引用、cron 四个职责互相咬合，
一次全改的爆炸半径覆盖「学生能不能答题」这个最关键路径。分三步，每步
都可独立回滚。

**A 阶段可以在本周内上线**（改动只是新增页面和只读接口，不碰任何现有
时间逻辑）。

## 8. 度量（上线前先定好，避免事后找理由）

| 指标 | 当前基线（2026-08-25） | 目标 |
|---|---|---|
| 日参与率（读段完成 / 在读人数） | 11/35 = **31%** | ≥ 50% |
| 三段全完成率 | —（新指标） | ≥ 30% |
| 背段完成率 | 3/35 = **9%** | ≥ 40% |
| 补段完成率 | 1/35 = **3%** | ≥ 30% |
| 词汇「已开始」占比 | **25%**（169/683） | ≥ 40% |
| 读段平均用时 | 未采（新增 `startedAt` 后可算） | 观察 |

**红线**：B 阶段上线两周内，若日参与率低于 A 阶段基线，立即回滚读段
的时间窗。

## 9. 待定问题

1. **周末要不要有课？** 现在周末无场次。改成「每日一课」后，周末是
   「没有课」还是「有课但不强制」？建议维持无课 —— 连续天数的上学日
   算法已经处理了这一点。
2. **读段 20 分钟对 O-Level 基础层是否够**？该层 5 题短答 + 3 词汇，
   今天的实际用时数据里没有（现在只记提交时刻）。A 阶段加 `startedAt`
   后先采一周数据再定，可能需要按层设不同时长。
3. **课程页要不要显示「今天不做也行」**？诚实但可能鼓励拖延。倾向不写，
   靠「大家通常在 8:30 做」的社会证明引导。
4. **卷内词汇题的分数是否脱离整卷分数门**（现在自动判分的词汇题也要等
   人工判完才显示对错）。若要即时反馈，需要单独放行 MCQ 类题目。

## 附：与 3.0 的关系

3.0 解决的是**内容**问题（五个难度层、词汇主线、卷内词汇题）。
4.0 解决的是**结构**问题（学习活动的时间和边界）。

3.0 的所有成果在 4.0 里原样保留 —— 卷子、词表推送、FSRS 调度、判分
流程一行不改，只是它们从「散落在两个时间窗里的动作」变成「一节课的
三个段落」。
