# PRD — 生词本与词汇复现（Vocabulary Loop）

> 需求来源：2026-07-31，用户提出「加一个生词本，文章里点词自动翻译，类似多邻国 / 百词斩」。
> 本文是**立项前调研结论 + 方案**，不是实现清单。核心结论与最初设想有三处重要出入，见 §2。
> 铁律不变：**代码零 Anthropic API 调用** —— 因此翻译走离线词典，不走任何 LLM。

---

## 1. 调研发现（全部有实测数据支撑）

### 1.1 本系统的语料太小，被动阅读不可能学会词

对生产库全部文章实测（`snapshotContent.passage`，去重后）：

| 指标 | 实测值 |
|---|---|
| 文章数 | 69 篇 |
| 总词次 | 43,139 |
| 不同词形 | 6,975 |
| **只出现过 1 次的词** | **3,472（50%）** |
| 出现 ≥6 次的词 | 1,049（15%） |

学界共识（Nation & Waring）：一个词需 **6–10 次遭遇**才初步习得，**约 20 次**才长期保持。
本系统 50% 的词学生一辈子只会见一次 —— **只做「点词翻译」而不做主动复习，等于没做**。
这是本次调研最重要的一条：它否定了「加个点词翻译就完事」的做法。

### 1.2 学生不会自觉复习 —— 靠自律的功能会被最需要的人无视

本周（7/28–7/31）实测：

| 正确率区间 | 人数 |
|---|---|
| 80–100% | 4 |
| 50–79% | 4 |
| 20–49% | 5 |
| **0–19%** | **9** |

每日到场 14–21 人 / 花名册 29 人。参与判分 22 人中 **14 人（64%）正确率低于 50%**。

推论：**多邻国式「每天自觉打卡 + 连胜 + 排行榜」在这个班会失败**。
它只会被本来就好的前 4 名使用，而正确率 <20% 的 9 人根本不会打开。
→ 复习必须**寄生在每天 8:30 那个全班必到的 30 分钟里**，不能是一个需要额外自律的独立入口。

### 1.3 本项目已有「自动采集」先例，应当复用其设计哲学

`StudentMistakes.tsx`（错题本）的注释写明：「智学网式：**批改即采集，错题自动归集**」。
但它只接**作业模块**，早测（真正的日常主力）没有任何采集闭环。
→ 生词本应同样以**自动采集为主、手动加词为辅**，而不是要求学生逐个手输。

### 1.4 竞品定位：不该克隆多邻国 / 百词斩

| 产品 | 核心机制 | 对本场景是否适用 |
|---|---|---|
| 多邻国 | 游戏化留存（连胜/排行/红心），通用语言入门 | ❌ 留存机制依赖海量用户与社交网络；29 人班做排行榜只会让后进生更抗拒 |
| 百词斩 | 图片联想记忆 + 考纲词库背诵 | ❌ 配图需海量版权与人力；且与「读懂这篇文章」脱节 |
| Anki | 纯 SRS，卡片全靠自建 | ⚠️ 算法可借鉴，产品形态过于硬核 |
| **Readlang / LingQ** | **阅读中点词即译 → 自动存词 → 卡片复习** | ✅ **最接近的形态**，正是本需求的成熟范式 |

**这些产品都免费且做得比我们好，学生想背单词早就有工具了。**
本系统唯一独占、别人给不了的是三样东西：

1. 学生**自己刚读过的那篇文章**（有上下文、有情绪记忆）
2. 学生**自己刚答错的那道题**（暴露了真实词汇缺口）
3. **每天 8:30 全班必到**的固定时段（唯一可靠的行为触点）

→ 因此产品定位是 **「读到 → 一点即查 → 自动进本 → 在早测里复现」的闭环**，
而不是「又一个背单词 App」。

### 1.5 技术可行性：零 API 前提下点词翻译完全可行

**ECDICT**（`skywind3000/ECDICT`，MIT 协议）：

- 76 万词条（增强版 222 万），含 `translation`(中文) / `definition`(英文) / `phonetic`(音标) / `pos`(词性占比)
- **`exchange` 字段直接解决词形还原**：编码 `p`过去式 / `d`过去分词 / `i`现在分词 / `3`三单 / `s`复数 / `r`比较级 / `t`最高级 / `0`原形。
  学生点 `shattered` 能正确查到 `shatter` —— 这是能否可用的关键，ECDICT 原生支持。
- `tag` 字段带考试标注（zk/gk/cet4/cet6/ielts/toefl/gre），可直接标出「这是雅思词」
- `bnc` / `frq` 词频 + `collins` 星级 → 可判断难度、决定是否值得入本
- 格式：CSV / SQLite / MySQL

**离线下发策略**（不把 76 万词塞进浏览器）：
一篇文章约 625 词、约 300 个不同词形 → 预生成该文的**词条子集**（几十 KB），
随试卷一并下发。结果：**零 API、零延迟、断网可用**，与现有 PWA 架构一致。

**间隔重复算法：FSRS**（`ts-fsrs`，MIT，TypeScript）
基于 7 亿次真实复习训练；同等记忆留存下比经典 SM-2 **少 20–30% 复习量**，
2023 年底起为 Anki 默认。在「每天只能挤出 3 分钟」的场景，这 20–30% 是决定性的。

## 2. 与最初设想的三处出入（需你确认）

1. **不做多邻国/百词斩式的独立背单词模块** —— 理由见 §1.2 / §1.4。
   改为「阅读锚定 + 寄生在早测里的复现」。
2. **点词翻译不能在考试进行中开放** ⚠️ **这条最重要**。
   早测里本来就有 vocab-in-context 词义题（`OLevelVocabInContext`）和词义类短答
   （如 'coax' / 'crumpled' / 'slick'）。考试中能点词查义 = **直接送答案**，
   且把阅读理解变成查词练习，**考试效度直接归零**。
   → 点词只在 **①交卷后的复盘页 ②练习模式 ③老师推送的预习材料** 开放。
3. **词典不是「自动翻译」而是「查词」**。整句机翻需要联网 API（违反铁律）且质量不可控；
   ECDICT 给的是词典释义（音标+词性+中文），这对备考实际上比机翻更有用。

## 3. 数据模型增量（纯新增，一次迁移）

```
DictEntry            (词典表，导入 ECDICT 子集，全局共享、非用户数据)
  word PK, lemma, phonetic, translation, definition, pos,
  tag String[], bnc Int?, frq Int?, collins Int?, exchange String?
  @@index([lemma])

StudentWord          (学生生词本)
  id, studentId, headword(原形), surfaceForm(点击时的形态),
  sourceType  enum(click | wrong_answer | teacher_push)
  sourcePaperQuestionId String?   // 来自哪道题
  sourcePassageTitle    String?   // 来自哪篇文章
  contextSentence       String    // 该词所在原句 —— 复习时必须带上下文
  state       enum(new | learning | review | known)
  // FSRS 调度状态
  due DateTime, stability Float, difficulty Float,
  elapsedDays Int, scheduledDays Int, reps Int, lapses Int, lastReview DateTime?
  createdAt
  @@unique([studentId, headword])
  @@index([studentId, due])

WordReviewLog        (复习流水，FSRS 参数优化需要历史)
  id, studentWordId, rating enum(again|hard|good|easy),
  reviewedAt, elapsedMs Int
  @@index([studentWordId])
```

数据量估算：29 人 × 5 词/天 × 180 天 ≈ 26,000 行 —— 可忽略。

## 4. 后端接口增量

```
GET  /vocab/lookup?word=&paperQuestionId=    查词（服务端做词形还原 → DictEntry）
POST /vocab/words                            加入生词本（带 contextSentence + 来源）
DELETE /vocab/words/:id                      移出
GET  /vocab/due                              今日待复习（FSRS due <= now，限 N 个）
POST /vocab/review                           提交 rating → ts-fsrs 算下次 due → 写 log
GET  /vocab/stats                            我的：总词数/已掌握/今日待复习/来源分布
GET  /vocab/glossary/:paperId                该卷所有文章的词条子集（离线预取用）
教师端:
GET  /vocab/class/:classId/top               全班高频生词（该讲什么）
POST /vocab/push                             老师推一批词给全班
```

采集规则（自动，无需学生操作）：
- 早测判分后，**答错的词义题目标词** → 自动入本（`sourceType=wrong_answer`）
- 复盘页学生点词 → 手动入本（`sourceType=click`）

## 5. 前端增量

**学生端**
- **复盘页**（`MyHistoryDetail`）文章渲染升级为**可点词**：点击 → 底部弹卡（音标/词性/中文/雅思标记）
  → 「+ 加入生词本」。⚠️ 考试进行中（`MorningQuizTake` test 模式）**不启用**。
- 新页 `/my-vocab`：我的生词本，按来源/文章/掌握度筛选，每条带原句。
- **复现入口（关键）**：早测**交卷后**自动出现「今日 5 个词 · 约 2 分钟」，
  复习完才进成绩页。不新增自律要求，寄生在既有仪式里。
- 卡片形式：给原句挖空 + 中文提示 → 想 → 翻面 → 四档评分（Again/Hard/Good/Easy）。
  **必须带原句**（他自己读过的那句），这是与百词斩最大的体验差异。

**教师端**
- 班级高频生词榜（今天该讲哪 5 个词）
- 一键把生词表推给全班
- 「生词 → 出题」：把高频生词灌进 vocab-in-context 题型，下周早测复现（形成真正的闭环）

## 7. 效果度量（本系统能自动测量，是独有优势）

- **采集率**：每次早测后有多少学生生词本 +≥1
- **复习完成率**：出现「今日 5 个词」后完成的比例
- **✅ 迁移证据（真正的效果指标）**：入本的词在**后续文章/题目中再次出现**时的正确率，
  对比未入本的同难度词。题库已有 `tags`（含 `vocab`），可直接算。
  —— 大多数背单词产品做不到这件事，因为它们没有学生的考试数据。

## 8. 豁免项论证（明确不做）

1. **社交/排行榜/连胜**：§1.2 数据显示 64% 学生正确率 <50%，排行榜对后进生是劝退不是激励。
2. **图片记忆卡（百词斩核心）**：配图版权与人力成本极高，且削弱「回到原句」的语境优势。
3. **整句机器翻译**：需联网 API，违反零 API 铁律；且会让学生跳过理解、直接读中文。
4. **AI 生成例句/助记**：违反零 API 铁律。原句即最好例句 —— 我们本来就有。
5. **全量考纲词库背诵**：AWL 仅 570 词族、Band 7 需 3,000–5,000 活跃词，
   与「读到才学」路线冲突；AWL 只用作**标注**（这词值不值得背），不做背诵主线。
6. **语音评测 / 发音打分**：早测是阅读场景，越界。

## 9. 不变的约束

- **零 Anthropic API**：查词=本地词典，调度=本地算法，例句=原文句子。全链路无 LLM。
- **考试期间禁用点词**（§2.2）—— 任何实现都不得破坏这条，否则考试效度归零。
- 迁移纯增量；`migrate deploy` 上生产。
- 移动端优先：主力设备是手机，点词热区、弹卡高度、误触（滑动 vs 点击）必须实测。
- 不新增学生自律要求：所有入口寄生在既有的 8:30 流程内。
