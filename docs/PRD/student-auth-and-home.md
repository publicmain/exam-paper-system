# 学生账号 + PIN + 个人主页 —— 设计与实施计划

> 状态：**已批准，实施中**　·　2026-08-25　·　决策人：叶老师
> 背景：外部审查 P0-1 指出「姓名即身份」；写路径已用扫码 token 关闭
> （commit `994edfc`），**读路径**（知道姓名即可看别人成绩/错题/生词）
> 需要真正的学生凭证才能关闭。叶老师批准引入「账号 + PIN」，
> 并要求同步重设计个人主页。

---

## 1. 目标与非目标

**目标**
1. 每个学生有一个 6 位数字 PIN，凭「姓名 + PIN」在**任何设备、任何时间**登录；
2. 登录后获得长效凭证（30 天），读写都走它；
3. 一个新的个人主页 `/me`：登录态的家，聚合「今天的课、我的数据、我的账号」；
4. 迁移不惊扰：明早的扫码答题流程**一秒都不能坏**。

**非目标（本期不做）**
- 不强制读路径必须登录（那是 Phase B 的开关，见 §7）；
- 不做邮箱/密码/验证码——学生没有可用邮箱，PIN 是这个年龄段的正确形态；
- 不做家长账号（现有一次性 token 链接不动）。

## 2. 身份体系总览（修改后）

```
                 ┌──────────────────────────────────────────┐
                 │              学生的三种凭证                │
                 ├──────────────┬──────────────┬────────────┤
                 │ scanToken    │ PIN token    │ handoff    │
                 │ 扫码签发      │ 登录签发      │ 跨设备接力  │
                 │ 当天 23:59   │ 30 天        │ 绑单场次    │
                 │ 教室场景      │ 任何地方      │ AirDrop    │
                 └──────────────┴──────────────┴────────────┘
                        ↓ 三者同为 role=student JWT ↓
        AuthGuard（认证）→ StudentIdentityGuard（对象级授权，已有）
```

**关键决策：PIN token 与 scanToken 同构**（同一 JWT 形状、同一签名密钥、
同一 Guard 链）。不新建认证体系 —— `StudentIdentityGuard` 与
`@RequireStudentToken()` 已经在生产运行，PIN token 天然通过。

**PIN token 允许在家答题**：这是已知且接受的语义（4.0 方向就是全天开放）。
答题的窗口约束由 morning-quiz 服务端独立校验，token 只回答「你是谁」。

## 3. PIN 设计

| 项 | 决定 | 理由 |
|---|---|---|
| 形态 | **6 位纯数字** | 10^6 空间；G11 学生手机键盘友好 |
| 存储 | bcrypt（cost 10，与教师密码同库同法） | 复用 `bcryptjs`，不引新依赖 |
| 弱 PIN 黑名单 | 全同（000000）、顺子（123456/654321）、年份（19xx/20xx） | 挡住前 5% 最常见选择 |
| 暴力破解 | **连错 5 次锁 15 分钟**（按学生计） + IP 限流 30/min | 10^6 ÷ 5次/15min ≈ 破解需数年 |
| 首次设置 | **扫码之后**（scanToken 在手 = 身份已被教室场景证实） | 不需要任何分发流程；老师零工作量 |
| 忘记 PIN | 教师在班级页一键重置 → 学生下次扫码后重设 | 35 人规模，人际信任即恢复通道 |
| 修改 PIN | 登录态下旧 PIN + 新 PIN | 标准做法 |
| 日志 | **PIN 永不落日志**（请求体不进 audit metadata） | 常识 |

**为什么「扫码后设置」而不是「老师分发初始 PIN」**：分发 = 老师造表、
打印、学生改密三步流程；扫码后设置 = 零流程，因为**能在教室扫到码并选中
自己名字**这件事本身就是身份证明（与现在 scanToken 的信任根同源）。

## 4. 数据模型

```prisma
model User {
  // ── 学生 PIN（2026-08-25）──
  pinHash        String?    // bcrypt；null = 从未设置
  pinSetAt       DateTime?
  pinFailedCount Int        @default(0)
  pinLockedUntil DateTime?
}
```

纯增量迁移，不碰任何既有行。

## 5. API

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| POST | `/api/student-auth/login` | 公开 + 限流 30/min | `{name, studentId?, pin}` → `{token, student}`；同名返回 `needDisambiguation` + 候选班级；连错 5 次锁 15 分钟 |
| POST | `/api/student-auth/set-pin` | **学生 token**（扫码或已登录） | `{pin}`；已设置过则拒（走 change） |
| POST | `/api/student-auth/change-pin` | 学生 token | `{oldPin, newPin}` |
| GET | `/api/student-auth/me` | 学生 token | `{id, name, pinSet}` —— 主页判断状态用 |
| POST | `/api/student-auth/admin/reset-pin` | 教师 JWT + 班级权限 | `{studentId}` 清空 pinHash |

扫码响应（`ScanResult`）新增 `pinSet: boolean` —— 扫码成功页据此弹
「设置 PIN」卡片。

## 6. 个人主页 `/me`

### 6.1 未登录

```
┌──────────────────────────────┐
│        我的每日英语           │
│  姓名 [____________]          │
│  PIN  [• • • • • •]           │
│        [ 登录 ]               │
│  ──────────────────────────  │
│  第一次用？在教室扫码后        │
│  即可设置 PIN                 │
│  或先用姓名查看成绩 →         │
└──────────────────────────────┘
```

同名学生：登录返回候选班级列表，点选后带 `studentId` 重试。

### 6.2 已登录（三段式，对齐 4.0「今天的课」）

```
┌──────────────────────────────┐
│ 你好，张三        [退出]      │
│ 🔥 连续学习 4 天              │
├──────────────────────────────┤
│ 今天的课                      │
│ ① 读  ✓ 已交 · 5/6 →         │
│ ② 背  ● 8/20 · 继续 →        │
│ ③ 补  ○ 3 道待练 →           │
├──────────────────────────────┤
│ 📊 成绩记录  📒 生词本         │
│ 📕 错题本                     │
├──────────────────────────────┤
│ 🔑 修改 PIN                   │
└──────────────────────────────┘
```

数据组合（**全部复用既有接口**，不新建 lesson API —— 那留给 4.0 正式版）：
- ① 读：`history-by-name`（今天有无提交/分数）+ `upcoming-for-name`（还开着的场次）
- ② 背：`vocab/stats`（新增 `reviewedToday` 字段 + `totalDue`）
- ③ 补：`mistakes/practice-queue`（队列长度）

**诚实约束**：完成判定沿 4.0 PRD §2.3 —— 可达成、只看「做了」。
连续天数暂用词汇 streak（唯一有历史数据的），标注「连续学习」而非「连续完成」。

### 6.3 扫码成功页新增

`pinSet=false` 时追加一张卡：
> 🔑 设置一个 6 位 PIN，以后在家也能登录看成绩、背单词
> [ • • • • • • ] [确认 PIN] [跳过]

可跳过（不挡答题）；每次扫码都会再提示，直到设置。

### 6.4 token 保管规则（防降级）

扫码现在**无条件覆盖** `auth_token`。若学生已持 30 天 PIN token，
扫码会把它降级成当天过期的 scanToken。修：扫码页写 token 前解码现有
token，**同一学生且现有的过期更晚 → 保留现有**。

## 7. 迁移与开关

| 阶段 | 内容 | 条件 |
|---|---|---|
| **A（本次）** | PIN 全套 + `/me` 上线；读路径照旧姓名可查 | — |
| **B（未来）** | `STUDENT_READ_REQUIRES_AUTH=on`：读路径也要 token，彻底关闭「知道姓名即可读」 | 全班 PIN 覆盖率 ≥90%，教师拍板 |

Phase B 的开关本次只**预留文档位**，不实现——避免误开把没设 PIN 的学生
挡在成绩外。

## 8. 安全清单

- [x] bcrypt 哈希，永不明文
- [x] 弱 PIN 黑名单
- [x] 账号级锁定（5 次/15 分钟）+ IP 限流
- [x] 锁定信息不泄露「该账号是否存在」之外的信息（统一 `invalid_credentials`）
- [x] PIN 不进日志/audit
- [x] token 同构复用既有 Guard，不引入第二套授权逻辑
- [x] 教师重置走 `canActOnClass`（只能重置自己班的学生）

| 层 | 内容 |

| service | 登录成功/失败计数/锁定/解锁、set 幂等拒绝、change 旧 PIN 校验、reset 清零 |

| 生产 E2E | 真机：设 PIN → 清 localStorage → 登录 → 主页 → 连错 5 次锁定 → 教师重置 |

## 10. 明早不炸清单

- 扫码流程只**加**了可跳过的 PIN 卡片，主链路（扫码→答题）零改动
- 所有新端点是新增路由，不动既有任何一条
- 迁移是 4 个 nullable 列，启动时 `migrate deploy` 秒级完成
- token 保管规则只影响「已有更长效 token」的场景（明早还没人有 PIN token）
